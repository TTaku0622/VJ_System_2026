## 起動

ローカルサーバー経由で開く（`file://` だとシェーダーと音源の読み込みに失敗する）。

```bash
cd ~/Desktop/VJ
python3 -m http.server 5502
# → http://localhost:5502
```

VS Code の Live Server 拡張でも可（ポートは `.vscode/settings.json` で 5502 に設定済み）。

### Scene01（`1`）白 / Scene02（`2`）黒

**塗るだけのシーン。**音にも反応せず、キーも持たない。曲間や MC で画を落とす（黒）、
フラッシュや客席を照らす（白）ための実用シーン。**単純であることがそのまま価値**で、
本番で確実に真っ白・真っ黒になることを優先している。

`P`（切替フェード）を ON にしておくと、レイヤー1を黒へ載せ替える操作がそのまま**フェードアウト**、
黒から戻す操作が**フェードイン**になる。

**暗転させたいだけならシーンを切り替えなくてよい。**MASTER FADER のマスター調光
（[出力全体の明るさ](#出力全体の明るさマスター調光)）を下げれば、どのシーンを出していても真っ黒になる。
Scene02 は「確実に黒を出す」ための保険として残してある。

### Scene03（`3`）幾何学 — 頂点が動く

**描くのは直線だけ**（折れ線は使わない。`line()` 以外の描画関数を呼ばない）。
「頂点」を1つ置き、そこから2本の直線（レイ）を下向きに伸ばす。角に見える部分は
折れているのではなく、**原点を共有した2本の直線が角度差を持っている**だけ。

| レイ | 向き | できる形 |
|---|---|---|
| A | 外下へ 45 度（`RAY_A_ANGLE`） | Λ の稜線に平行な斜め線群 |
| B | 真下 | 階段状の縦線 |

頂点は起点から外下へ等間隔（`LOCUS_ANGLE` / `PIN_SPACING`）に並ぶ。**起点自身も
頂点**なので、そこから出るレイ A が Λ の外周になる。中央の縦軸で左右対称。

#### アニメーション

線は「**動く頂点 → キャンバス端の固定点**」を結ぶ線分として描く。端の点は base の
状態で一度決めたら動かさないので、**画面の縁での線の位置が固定される**。頂点が動くと
端が固定されているぶん、線の角度が変わる。

頂点には2つの役割があり、稜線の並び順に**1つおきで交互**に割り当てる。

| 役割 | 動き |
|---|---|
| **上へ動く頂点** | 上へ登りながら、少しだけ内側へも寄る（`riseInward`） |
| **内側へ動く頂点** | 中央軸へ寄りながら、ほんの少しだけ上へも動く（`INWARD_RISE_LEVELS`）。**内寄せが 1 を超えると軸を越えて反対側へ入り込む** |

役割が交互に並ぶので、動きの小さい側が骨組みとして残り、大きい側がその間に食い込んで
細かい交差が生まれる。

起点の頂点（軸上）は「内側へ動く」側に割り当てている（`parityOffset = 1`）。軸上の
頂点は内寄せで動かないため、外周の Λ が残って三角形の輪郭が保たれる（`O` キーで反転）。

端の固定点は `_edgeAnchor()` がスラブ法で求める。矩形との交差区間の遠い側を返すので、
頂点がキャンバスの外へ出ても正しく求まる。

| キー | 動作 |
|---|---|
| `Q` | base に戻す |
| `W` | 自動進行 ON/OFF |
| `A` / `S` | 進行を手動で 戻す / 進める |
| `Z` / `X` | 上昇の距離 −/＋ |
| `R` / `T` | 上昇の内側寄り −/＋ |
| `C` / `D` | 内寄せの量 −/＋（1 を超えると軸を越える） |
| `U` | 内寄せの上昇（4段階で循環。空きキーが1つのため −/＋ ではない） |
| `O` | 役割の割り当てを反転 |
| `E` | 頂点の数（片側 4〜24 で循環） |
| `Y` | 左右対称 ON/OFF |
| `G` | 現在値をコンソールに出力（定数へ書き戻す用） |

既定値は `base.jpg` の実測（稜線 31 度 / 斜め線 45 度 / 間隔は画面高さの 11.6%）。
配色は黒背景 × 白線で固定（`BG_COLOR` / `LINE_COLOR`）。
**音への反応は未実装**（MIDI で後から付ける）。

### Scene04（`4`）スペクトル同心シェイプ

スペクトルの値をそのまま図形の大きさにして、中心から相似形を何重にも重ねる。
バンド間を線形補間して本数を増やしてあるので、隣り合う線が少しずつずれて縞になり、
音が動くと縞がうねる。`T` で **円 ↔ 三角** を切り替える（同時には出さない）。

| モード | 大きさの決め方 |
|---|---|
| 円 | 値をそのまま直径にする（`CIRCLE_MAX_SIZE` = 画面短辺の 130%） |
| 三角 | 値を `TRI_MIN_SIZE`〜`TRI_MAX_SIZE`（画面短辺の 22%〜180%）へ写す |

三角は**下限があるので音が小さくても形が残る**。どちらも上限は画面短辺を超えるので、
鳴ったときは画面の外まで開く。三角は上向き固定で、底辺は高さの 1.5 倍（`TRI_BASE`）。
線の太さは中心側（低域）が細く、外側（高域）ほど太い。

**キーは `T`（円 ↔ 三角）だけ**。他の調整はクラス冒頭の定数で行う。
切替は `modes`（後述）で宣言してあるので、操作画面にも現在どちらかが出る。

### Scene05（`5`）回転する四角のトンネル

中心から生まれた四角が、1枚ごとに少しずつ回りながら外へ広がる。動きは3つ。

| 動き | 音の反応 |
|---|---|
| **全体の回転** | **なし**（`SPIN_SPEED` 固定）。無音でも必ず動いている状態を作るため |
| **外への流れ** | 音が大きいほど速い（`FLOW_QUIET` / `FLOW_LOUD`） |
| **ひねり**（1枚ごとの回転差） | 音が大きいほど渦が締まる（`TWIST_QUIET` / `TWIST_LOUD`） |

四角の大きさは中心（0）から等間隔なので、**流れが四角1枚ぶん進むと元と同じ形に戻る**。
`flowPhase` を 1 で剰余すれば継ぎ目なくループする。**流れたぶんの回転をループ前に一度かけておく
必要がある**（`rotate(spin + flowPhase * twist)`）。これを忘れると継ぎ目で角度が飛ぶ。

中心で生まれる数枚は薄く描いて（`FADE_IN_RINGS`）、湧き出す瞬間を隠している。

枚数は画面サイズから計算する（決め打ちしない）。**回転しても中心から辺までの距離は一辺の
半分のまま**なので、一辺が画面の対角線に達すればどの角度でも四隅まで覆える。

**キーは持たない。**調整はクラス冒頭の定数で行う。

### Scene06（`6`）カメラ

カメラ映像を出すシーン。加工は `shader/camera.frag` の中で `u_mode` を切り替えて行う。
アスペクト比は保ったまま画面いっぱいに敷き、はみ出す方向を中央基準で切る（引き伸ばさない）。

| キー | 動作 |
|---|---|
| `Q` / `W` / `E` | カメラを選ぶ（1台目 / 2台目 / 3台目） |
| `R` | カメラを再取得（映像が止まったときの復帰用） |
| `A` | オリジナル |
| `S` | 枠線のみ |
| `D` | 古いテレビ（ノイズ・走査線） |
| `F` | ゆがみ |
| `G` | 2値化（シルエット） |
| `H` | 残像 |
| `J` | ストロボ（バスドラで発光） |

ポストシェーダー側の `B`/`V`（ミラー）、`N`/`M`（モザイク）、`L`/`K`/`,`（画面分割）も
そのまま重ねて使える。

#### 枠線のみ（`S`）

Sobel で明暗の変化が大きいところだけを白線にする。**人の輪郭も背景の輪郭も等しく線になる**
ので、被写体に寄って撮るほど人の形が読める。AI の推定ではないので検出が飛ぶことがなく、
ライブ照明でも崩れない。配色は黒背景 × 白線。

音が大きいほどしきい値が下がり、細かい線まで出る。**無音でも強い輪郭は残る**ので絵は消えない
（`THRESHOLD_QUIET` / `THRESHOLD_LOUD`）。線の太さは `EDGE_SPREAD`、手元カメラ用の左右反転は
`MIRROR` で、いずれもクラス冒頭の定数。

**しきい値の既定は仮の値**。実際のカメラと会場の照明で線の量が変わるので、リハで詰める。

#### 古いテレビ（`D`）

「古いテレビらしさ」は単一の効果ではないので、6つを重ねている（`camera.frag` の `oldTv()`）。

| 要素 | やっていること |
|---|---|
| 走査線 | 1行おきに暗くする（`TV_SCANLINES` / `TV_SCAN_DEPTH`） |
| ざらつき | ピクセル単位の乱数を加算（`TV_NOISE_MIN`〜`MAX`） |
| 行ごとの横ずれ | 同じ行は同じ量ずれるので横方向に切れ目が揃う（`TV_JITTER_MIN`〜`MAX`） |
| 同期ズレ | まれに行がまとめて大きく飛ぶ（`TV_TEAR_CHANCE` / `TV_TEAR_AMOUNT`） |
| 色ずれ | R と B だけ左右にずらして取る（`TV_CHROMA`） |
| ロールバー | 明るい帯がゆっくり縦に流れる（`TV_ROLL_SPEED` ほか） |

最後に四隅を落とし（`TV_VIGNETTE`）、コントラストを下げて褪せさせる（`TV_CONTRAST`）。

音が大きいほどざらつきと横ずれが増えるが、**無音でも最小量は残る**ので「普通の映像」には
戻らない。逆に**上げすぎると絵が読めなくなる**ので、`TV_NOISE_MAX` は 0.20 に抑えてある。

調整値は `camera.frag` 冒頭の `TV_` 定数にまとめてある（音で動く2つ以外は uniform にしていない）。
**`TV_GRAIN_SCALE` を小さくするとざらつきが点ではなく横縞になる。**乱数へ渡す UV が
横方向にゆっくり変化して隣のピクセルと相関するためで、拡大してから渡す必要がある。

#### 2値化（`G`）

明るさをしきい値で白と黒に割るだけ。**`S`（枠線）の対**で、あちらが人を「線」で出すのに対し
こちらは「面」で出す。`A` 原寸 → `S` 線 → `G` 面 と性格が分かれるので、切り替えるだけで画が変わる。

音が大きいほどしきい値が下がり（`BIN_QUIET` → `BIN_LOUD`）白い面が広がる。`BIN_SOFTNESS` を
上げると境界がぼけて2値でなくなるので、小さいままにしておく。

#### 残像（`H`）

前フレームの出力を**ぼかして**少し拡大し、減衰させて、今のフレームと**明るい側を採用**（`max`）する。
明るい動きが軌跡として外へ広がりながら消えるので、演者が腕を振ると光の帯が伸びる。

ぼかしは中心＋斜め4点の5タップ（`blurredPrev()`）。**フィードバックなので毎フレーム掛け合わさり**、
1フレームぶんは弱いぼかしでも軌跡全体はかなり柔らかくなる。強さは `TRAIL_BLUR`（ピクセル）。

**`TRAIL_BLUR` を上げすぎると5タップの形が斜め十字の筋として見えてしまう**（目安 6〜8px 以上）。
それ以上ぼかしたいときは半径を上げるのではなく、タップ数を増やすか2パスに分ける。
また**ぼかすとエネルギーが広がって軌跡が暗くなる**ので、`TRAIL_DECAY_*` も一緒に上げる必要がある。

**このモードだけ実装の性質が違う。**シェーダーは書き込み中のバッファを読めないので、
`scene06.js` に前フレームを写す専用バッファ（`this.prev`）を持たせてある。転送は残像モードの
ときだけ行う。モードに入る瞬間に `prev.clear()` しているのは、前回の軌跡が一瞬見えるのを防ぐため。

**座標系に注意。**`u_prev` は加工後の出力（画面座標）なので `vTexCoord` で引く。
カメラは cover 補正後の `uv` で引く。混ぜると像がずれる。

`TRAIL_DECAY_MAX` を 1 以上にすると**白く飽和して戻らなくなる**ので上げすぎない。

#### ストロボ（`J`）

**バスドラの立ち上がり**で一瞬だけ明るくする。音量の大小ではなく「前フレームより低域が増えた
瞬間」を拾うので、打点に合う。検出は `scene06.js` の `_updateFlash()`。

⚠️ **光感受性への配慮を実装に組み込んである。**

- 全面を白で塗らず、**明度の上げ下げに留めている**（`STROBE_BASE` / `STROBE_GAIN`）
- **`STROBE_MIN_INTERVAL` = 200ms** で発光の最短間隔を制限し、5Hz を超えないようにしている

**この下限は外さないこと。**激しい明滅は光感受性発作を誘発しうる。会場側にルールがある場合も
あるので、本番前に大学の担当に確認する価値がある。

#### 加工を増やす

1. `shader/camera.frag` に `u_mode` の分岐を足す
2. `scene06.js` の `modes.keys` と `modes.labels` に1つずつ足す（並び順が `u_mode` の値になる）

2 を足して 1 を忘れると**画面が黒くなる**（`camera.frag` 末尾のフォールバック）。

**ホームポジション `A` `S` `D` `F` `G` `H` `J` は使い切った。**続きの `K` `L` は画面分割なので、
8つ目からは下段の `Z` `X` `C` か上段の `T` `Y` `U` へ移る。

**空いている文字は `C` `O` `T` `U` `X` `Y` `Z` の7つだけ**（グローバルが8文字、Scene06 が11文字を
使用）。他シーンのキーはシーン固有なので重複してよいが、グローバルとは衝突させられない。
**キーが足りなくなる前提で MIDI へ逃がせるようにしてある**（[MIDI コントローラー](#midi-コントローラー)）。
パッド1枚にキー1つを割り当てるので、キーボード側の文字数の制約から解放される。

### Scene07（`7`）どくどく格子

Life is Tech! の課題「リピーター２」をオリジナル化したものの移植。格子状に並んだ四角が、
音に合わせて大きさと枠の太さを変える。仕掛けは3つ。

| 仕掛け | 中身 |
|---|---|
| **自動ゲイン** | 直近の平均（`rawAvg`）と減衰する最大値（`rawMax`）を覚えておき、そのときの音量に合わせて 0〜1 へ引きのばす。**音源の音量が変わっても勝手に合う** |
| **非対称の追従** | 大きくなる時は速く（`PULSE_ATTACK`）、戻る時はゆっくり（`PULSE_RELEASE`）。心臓の鼓動っぽい動きになる |
| **遅延参照** | 脈を `history` にためて、中心から遠いマスほど古い値を見る。**波が中心から外へ広がる** |

大きさ用の脈（`pulse`）と枠の太さ用の脈（`edge`）は**わざと速さを変えてある**。同じ値を使うと
「ふくらむ＝太くなる」で単調になるため。太さは `edge` を2乗して使うので、細い時はうんと細く、
強く鳴った時だけ太くなる。

マスの間隔は画面の高さ基準（`CELLS_IN_HEIGHT` = 6.25。元の 500px × 6 マスと同じ密度）。
四角3枚ひと組の大きさは、その間隔に `SET_SCALE`（0.8）をかけた `unit` を基準にする。
大きさと太さの比率は**合計が `unit` の 0.975 に収まる**ので、いちばんふくらんだ時でも隣と
ぶつからない。**セット同士の余白を広げたいときは `SET_SCALE` だけを下げる**（形も音への
反応も変わらない）。1.0 にすると最大時に隣とほぼ接する（元のスケッチはこの状態）。

1マスは**四角3枚の入れ子**で描く。大きさは外から `size + band` / `size` / `size - band`。

| 層 | 色 |
|---|---|
| 外 | 座標の色を `OUTER_SHADE`（0.45）で暗くしたもの |
| 中 | 座標の色そのまま |
| 内 | 白（`FILL_COLOR`） |

3枚はすきまなく重ねる（層のあいだを空けると別物になる）。セット同士の間隔は `SET_SCALE` で調整する。

元のスケッチは**太い線を1本引いていただけ**。線は輪郭の中心に引かれるので内側の半分が
白い面（`fill` を書いていない＝ p5 の既定の白）と重なり、結果として同じ3層になっていた。
ただしその作りでは**層ごとの濃さを調整できず、中の白が色に埋もれて見分けづらい**ので、
同じ大きさの四角を3枚重ねる形に置きかえた。`noFill()` にすると別物になるので注意。

色は **HSB** で作り、**色相が時間で回り続ける**（`HUE_SPEED` = 0.3 度/フレーム ≒ 20 秒で一周）。
位置による差は元と同じ幅にしてあるので、グラデの形は保ったまま全体が移り変わる。

| 定数 | 役割 |
|---|---|
| `HUE_SPREAD_X` = 52 | 左右の色相差（元の 赤 → 黄 と同じ幅） |
| `HUE_SPREAD_Y` = -60 | 上下の色相差（元の 赤 → マゼンタ と同じ幅） |
| `SAT_NEAR` / `SAT_FAR` | 左上が濃く、右下が白っぽい（元と同じ） |

**色相は音では変えない。**無音でも色だけは動き続けるようにするため（Scene05 の回転と同じ考え）。
元は `stroke(255, x / 2, y / 2)` と RGB 固定で、しかも**フルスクリーンだと座標が大きすぎて 255 に
飽和し白一色になる**ため、そのままでは使えなかった。背景は他シーンに合わせて黒（元は濃紺 + 脈で明滅）。

`rawMax` には下限（`MAX_FLOOR`）を置いてある。**これが無いと長い無音で 0 に落ちて、正規化が
0 除算になり画面が消える。**元のスケッチは曲を流す前提だったので下限が無かった。

**キーは持たない。**調整はクラス冒頭の定数で行う。

### Scene08（`8`）流体

**ノイズで座標をずらしてから縞を描く**（domain warping）。絵の具や墨が混ざっていくような
流れになる。描画はすべて `shader/fluid.frag` の中で、`scene08.js` は音を uniform に
変換して渡すだけ。

**流体の計算（ナビエ・ストークス）はしていない。**本物の計算は速度場を前フレームから
作り直す必要があってバッファを2枚持つことになるが、VJ に要るのは「流れて見えること」
なのでノイズで足りる。

| 手順 | 中身 |
|---|---|
| 1 | 画面の座標を中心原点にする（横長でも形が伸びないよう縦基準） |
| 2 | ノイズ2枚を x と y のずれとして使って座標をゆがめる ＝ **流れ** |
| 3 | 必要なら折り返す（鏡） |
| 4 | ゆがめた座標から縞の位置を作る（横縞 ↔ 渦） |
| 5 | 縞の位置で配色を引く |

参考にしたのは OpenProcessing の [Rainflower Stone](https://openprocessing.org/sketch/2697293)
（元は Zaron Chen "Unified Rupture"）。**組み立てだけを借りて、コードは書き直してある。**

#### 音の反応

| 反応 | 中身 |
|---|---|
| **流れの速さ** | 音が大きいほど速く混ざる（`FLOW_QUIET` / `FLOW_LOUD`） |
| **ゆがみ** | 音が大きいほど渦が乱れる（`WARP_QUIET` / `WARP_LOUD`） |
| **寄り** | 低域の脈で画面ごと少し寄る（`ZOOM_RANGE`。立ち上がりは速く戻りはゆっくり） |

**無音でも止まらない**（`FLOW_QUIET` / `WARP_QUIET` が 0 でない）。明るさも
`BRIGHT_QUIET` までしか落ちないので絵が消えることはない。

#### キー

| キー | 動作 |
|---|---|
| `A` `S` `D` `F` | 配色（雨花石 / 墨 / 溶岩 / 虹） |
| `Z` | 渦 ↔ 横縞（切替は数秒かけて補間する） |
| `X` | 鏡（上下左右）ON/OFF |

配色は `modes` で宣言してあるので操作画面にも出る。`Z` `X` はトグルなので `modes` には
入れていない。**虹の配色だけは色相が時間で回り続ける**（音では変えない。Scene07 と同じ考え）。

#### 落とし穴

| | |
|---|---|
| **鏡は「ゆがませた後」に折り返す** | 先に折ると折り目の左右でノイズの値が違い、画面の中央に**十字の切れ目**が出る。後から折れば模様がつながったまま左右対称になる |
| **`SWIRL_TURNS` は整数にする** | 角度は1周で 0 に戻るので、整数でないとその継ぎ目が1本の線として画面に出る |
| **色は折り返して引く** | `fract` の値をそのまま配色に使うと 1 と 0 の継ぎ目が線になる。`abs(fract(x)*2-1)` で往復させる |
| **`precision highp float`** | `mediump` だとシンプレックスノイズの整数計算が壊れて四角いムラが出る |
| **流れは位相を積む** | 「時間 × 速さ」で渡すと、音で速さが変わった瞬間に絵が飛ぶ。`scene08.js` で毎フレーム足した `flow` を渡している |
| **渦の中心をぼかす** | 縞が1点に集まって針のように尖るので、**縞ではなく色のほうを**中心でぼかす（`EYE_SOFT`）。縞をぼかすと角度の継ぎ目がずれて線が出る |

#### 重さ

1フレームあたり **2.5ms**（実測。2578×1862 = Retina のフルウィンドウ）。60fps に必要な
16.7ms に対しては余裕があるが、**重くなったらまず `OCTAVES` を減らす**（3 → 2 でノイズの
呼び出しが 1/3 減る）。見た目を落ち着かせたいときは `WARP_LOUD` を下げ、濃い色を細い筋に
したいときは `SHADE_BIAS` を下げる。

### Scene09（`9`）白線

**縦・横それぞれ3本の白線を引くだけ**のシーン。**拍に合わせて位置を自動で引き直す。**
`Q` を押すとその場でも引き直す。起動時にも1回引いているので、最初から位置はばらばら。

#### 拍に合わせた引き直し

| キー | 間隔 | 120 BPM のとき |
|---|---|---|
| `A`（起動時） | 1/4（四分音符 = 1拍ごと） | 毎秒 2回 |
| `S` | 1/8（半拍ごと） | 毎秒 4回 |
| `D` | 1/16（1/4拍ごと） | 毎秒 8回 |

拍は [テンポ](#テンポbpm) の BPM から取るので、**TAP TEMPO で合わせればそのまま曲に乗る。**
「通算の拍数 × 割る数」の整数部が変わった瞬間に引き直す（`_shuffleOnBeat()`）。フレーム数では
なく拍の位置で見ているので、fps が落ちても拍の頭からずれない。fps より刻みが細かいときは、
間の刻みを飛ばして1回だけ引き直す。

⚠️ **1/16 は速い。**200 BPM なら毎秒 13 回、画面の明るい場所が入れ替わる。線は細いので
Scene06 のストロボ（全面の明滅。5Hz 上限あり）ほどではないが、つまみで太くしたうえで 1/16 にすると
画面に占める光の面積が増える。光感受性への配慮として、太い線と 1/16 の組み合わせは長く続けない。

| 定数 | 役割 |
|---|---|
| `LINE_COUNT` | 縦・横それぞれの本数（3） |
| `LINE_WEIGHT` | 芯の線の太さ（ピクセル） |
| `GLOW_WIDTH` | いちばん外側の光の太さ＝光の広がり |
| `GLOW_LAYERS` | 光を重ねる枚数。多いほどなめらか |
| `GLOW_ALPHA` | 1枚あたりの濃さ＝光の強さ |
| `WEIGHT_SCALE_MIN` / `MAX` | つまみで動かす太さの倍率（1.0〜6.0） |

**位置は完全にランダム。**`random(width)` / `random(height)` をそのまま使っていて、線どうしの
間隔も端からの余白も見ていない。2本が重なる回や、画面の縁に張りつく回もそのまま出る。

#### 発光

**太くて薄い線を、外側から内側へ重ねて作る。**縁に向かって暗くなる光の帯ができ、最後に引く
芯の白と合わさって光って見える。芯を最後に引かないと、光るだけで線が読めない。

**canvas の影（`shadowBlur`）は使っていない。**にじみは滑らかになるが、**画面いっぱいの線に
かけると1枚あたり 10ms 近くかかり、4枚重ねて 43ms/フレームまで落ちた**（実測。60fps に必要な
16.7ms の 2.5 倍）。線を重ねる今の方式は **1.3ms/フレーム**で、見た目もほとんど変わらない。

#### 太さをつまみで動かす

MIDI のつまみ（Device control の1番）で**芯と光をまとめて太らせる**。
`weightScale` が 1.0〜6.0 で動き、芯 3→18px、光 26→156px になる。

**絞りきった状態（1.0）が上の定数そのままの見た目。**下げても元に戻るだけなので、
本番でつまみがどこにあっても絵が壊れない。

芯だけ太くしていないのは、**光の帯との比が崩れて「太い線」ではなく
「光っていない白い棒」に見える**ため。

**音（音量）への反応は無し。**キーは `A` `S` `D`（間隔）と `Q`（その場で引き直す）。

## レイヤー（Resolume 式）

**シーンをレイヤーに載せて、下から順に重ねて出す。**Resolume でいうクリップがシーン、
レイヤーがそのままレイヤーにあたる。実装は `sceneManager.js` と `shader/main.frag`。

```
レイヤー3  白線     加算   100%    ← いちばん上
レイヤー2  カメラ   通常    40%
レイヤー1  流体     通常   100%    ← いちばん下
```

| レイヤーが持つもの | キーボード | MIDI |
|---|---|---|
| シーン（1つ。空でもよい） | `1`〜`9` で載せる / `]` で空に | グリッド列1〜3 / CLIP STOP |
| 不透明度（0〜1） | `↑` `↓` | フェーダー1〜3 |
| 合成モード | `[` | RECORD ARM |
| バイパス（一時的に消す） | — | ACTIVATOR（点灯 = 出ている） |
| ソロ（ソロのレイヤーだけ出す） | — | SOLO |

**起動時はレイヤー1に Scene01 だけが載っている。**触らなければ以前と同じ見た目になる。

### 合成モード

**全シーンが背景を不透明に塗っている**ので、「通常」で重ねると下のレイヤーは見えない
（不透明度で混ぜる＝手動のクロスフェードになる）。黒背景のシーンを上に乗せるときは
**加算**か**スクリーン**を使う。シーン側を透明背景に書き換える必要はない。

| モード | 見え方 | 使いどころ |
|---|---|---|
| 通常 | 上が下を覆う | 不透明度で混ぜる |
| 加算 | **黒が透明になり**、明るい所が足される | 白線（Scene03 / 09）を流体やカメラに乗せる |
| スクリーン | 加算より白く飛びにくい | 同上 |
| 乗算 | **白が透明になり**、暗い所が乗る | 2値化したカメラをマスクのように使う |

起動時の合成モードはレイヤー1・2 が通常、レイヤー3 が加算（`DEFAULT_BLENDS`）。

### 選択中のレイヤー

**キーと MIDI のシーン操作**（`modes` の切替・`keyHelp`・つまみ）は、**選択中のレイヤーに
載っているシーン**に届く。シーンを出すとそのレイヤーが選ばれるので、出したシーンの操作が
そのまま効く。操作画面の大きな数字と、APC40 の右下 15 個の意味もこれで決まる。

選び直すのは `←` `→` か TRACK SELECTION。

### デッキ（どのレイヤーで何を出すか）

`sceneManager.js` の `deck` に、レイヤーごとに出せるシーンを上の段から書く。
**MIDI グリッドの列1〜3 がそのままこの表になる。**

```js
this.deck = [
    ['8', '5', '7', '2', '1'],          // レイヤー1  背景（流体 / トンネル / 格子 / 黒 / 白）
    ['6', null, null, null, null],      // レイヤー2  カメラ
    ['9', '3', '4', null, null],        // レイヤー3  上に乗せる線画（白線 / 幾何学 / 同心）
];
```

- **SCENE LAUNCH**（APC40 右端）で横一列（同じ段）をまとめて出せる（Resolume の Column）。
  **空きのマスのレイヤーは触らない。**押した瞬間にカメラが消える、といった事故を避けるため
- 数字キーはデッキと関係なく、選択中のレイヤーに載せる
- **同じシーンを2つのレイヤーに載せることもできる。**描くのは1回だけなので、同じ絵が2枚重なる
  （2回描くとアニメーションが倍速になってしまうため）

### 切替フェード（`P`）

以前のクロスフェード。ON にすると、レイヤーにシーンを載せ替えたとき**そのレイヤーの中で**
**1小節（4拍、`FADE_BEATS`）**かけて前のシーンから混ぜる（Resolume のレイヤーの Transition）。
長さは [テンポ](#テンポbpm) の BPM で決まる（120 BPM なら 2秒）。
空のレイヤーに載せたときは不透明度を 0 から上げる。遷移中の載せ替えは無視する。

### 重さ

**出ているレイヤー（空でない・不透明度 > 0・バイパスでない）のシーンだけを描く。**
出ていないレイヤーのシーンは止まっていて、出した瞬間に続きから動き出す。
出ていないレイヤーには 1×1 の黒を渡している。2D のシーンはテクスチャとして毎フレーム
GPU へ転送されるので、描いていない大きなバッファを渡すと無駄に重くなるため。

**3枚同時（特にカメラ＋流体）で 60fps が出るかは実機で要確認。**操作画面の fps で見られる。

### 枚数を変える

1. `sceneManager.js` の `LAYER_COUNT`（あわせて `DEFAULT_BLENDS` と `deck` の行数）
2. `shader/main.frag` の `u_layerN` の組と、`main()` の合成の行を同じ数にする。
   **GLSL ES 1.0 ではテクスチャを配列で回せない**ので、1枚ごとに書き下してある
3. `midiMap.js` の `layers`（グリッドの列とボタン列）と `knobs.global`（フェーダー）

## テンポ（BPM）

**BPM と拍の位置を持つ時計**（`js/tempoManager.js`）。Resolume の BPM 欄にあたる。
拍は**フレーム数ではなく実時間**から出すので、fps が落ちても拍とずれない。

| やりたいこと | MIDI（APC40） | キーボード | 操作画面 |
|---|---|---|---|
| 叩いて合わせる | TAP TEMPO | `Tab` | TAP ボタン |
| 数値で指定する | — | — | 入力欄 →「指定」 |
| ±1 する | TEMPO つまみ（1目盛り ±1） | `Shift` ＋ `↑` `↓` | −1 / ＋1 |
| 拍を少しずらす | NUDGE − / ＋ | `Shift` ＋ `←` `→` | ◀ 遅らせる / 早める ▶ |
| いまを1拍目にする | METRONOME（TAP の1打目でも） | `-` | 頭をそろえる |

- **タップは叩いた瞬間を拍の頭にそろえる。**2秒以上空けてから叩きはじめると新しい並びになり、
  **その1打目が小節の1拍目**になる。曲の頭から4回叩けば BPM と小節の頭が同時に合う
- BPM は直近8回の間隔の平均（0.1 刻み）。範囲は 60〜200
- **BPM を変えても拍の位置は飛ばない**（0拍目の時刻を付け替えている）
- NUDGE は1回で 0.05 拍。BPM は変えずに位置だけ前後させる
- 操作画面に BPM と4つの拍ランプ（1拍目は緑）が出る

いま BPM を使っているのは**切替フェードの長さ**だけ。シーンから使うときは `BaseScene` のヘルパーを読む。

| メソッド | 内容 |
|---|---|
| `this.bpm()` | いまの BPM |
| `this.beatPhase()` | 拍の中の位置 0.0〜1.0（0 が拍の頭） |
| `this.beatInBar()` | 小節の中の何拍目か 0〜3 |
| `this.barPhase()` | 小節の中の位置 0.0〜1.0 |

## シーンを追加する

1. `js/scenes/scene03.js` を作り、`BaseScene` を継承したクラスを書く

```js
class Scene03 extends BaseScene {
    constructor() {
        super(WEBGL);       // 2D なら super()
    }
    setup() { }
    draw(spectrum) {
        this.pg.background(0);
        // this.pg に描く
    }
}
```

2. `index.html` に `<script src="js/scenes/scene03.js"></script>` を追加
3. `sketch.js` の `setup()` で `sceneManager.addScene(new Scene03());`

   （どのレイヤーの列に置くかで、重なり方が決まる）

## シーンに「切替」を持たせる

シーンのコンストラクタで `this.modes` を宣言すると、**キー操作の処理と操作画面への表示が
自動で効く**。シーンごとにバラバラの書き方をしないための約束。

```js
// 1キーで循環（Scene04）
this.modes = { keys: ['T'], labels: ['円', '三角'] };

// キーごとに直接選択（Scene06）
this.modes = { keys: ['A', 'S'], labels: ['オリジナル', '枠線'] };
```

`keys` が1つなら押すたびに循環、複数なら `keys[i]` で i 番を選ぶ。あとは `keyPressed` で
`this.handleModeKey(key)` を呼ぶだけ。現在値は `this.modeIndex`（`BaseScene` が持つ）。

| メソッド | 内容 |
|---|---|
| `this.handleModeKey(key)` | 切替キーなら処理して `true` を返す |
| `this.setMode(index)` | 切替を直接指定する。**表示していないシーンにも呼べる** |
| `this.onModeChanged(index)` | 任意。切替時の後始末を書く（Scene06 は残像バッファを消している） |

**切替の変更は必ず `setMode()` を通る。**キー操作でも、将来の操作画面からの遠隔操作でも
同じ入口になるので、後始末の書き場所が1か所で済む。

## オーディオ

`draw(spectrum)` の `spectrum` は 0.0〜1.0 に正規化した 32 バンドの配列。
`BaseScene` のヘルパーで帯域を取れる。

| メソッド | 内容 |
|---|---|
| `this.bass(spectrum)` | 低域（bin 0〜2） |
| `this.mid(spectrum)` | 中域（bin 3〜10） |
| `this.treble(spectrum)` | 高域（bin 11〜31） |
| `this.level(spectrum)` | 全体の平均 |
| `this.avg(spectrum, s, e)` | 任意の範囲の平均 |

**起動時の入力はマイク**（`audioManager.js` の `source`）。開いた直後にブラウザが
マイクの許可を求めるので許可する。AudioContext はユーザー操作があるまで止まっているので、
**画面をクリックするかスペースを押すまで解析値は 0 のまま**（絵が出ない）。

音源ファイルを使うときは `asset/sound/` に置いて `sketch.js` の `preload()` のコメントを
外し、`I` キーでファイル入力に切り替える。本番でミキサーから音を取るときはマイク側
（ライン入力）のまま使う。

シェーダー側では `u_vol` / `u_bass` / `u_mid` / `u_treble` が同じ値で使える。

## カメラ

`cameraManager` が**カメラを1本だけ開いて全シーンで共有する**。同じデバイスをシーンごとに
`createCapture` すると USB の帯域を二重に食うため。配線と機材の話は
[camera-setup.md](camera-setup.md) を参照。

| メソッド | 内容 |
|---|---|
| `cameraManager.isReady()` | 映像が使えるか。false の間は描画をスキップする |
| `cameraManager.get()` | テクスチャとして使う `p5.MediaElement` |
| `cameraManager.aspect()` | カメラのアスペクト比 |
| `cameraManager.select(i)` | i 番目のカメラを選ぶ（`Q` `W` `E` キー） |
| `cameraManager.reopen()` | 開き直す（`R` キー） |

**起動時は PC の内蔵カメラ**（`deviceId` を指定せずに開くので既定のデバイスになる）。
外部カメラを繋げば `W` `E` で選べるようになるので、コードの変更は要らない。
現在のカメラ名は切り替えるたびにコンソールへ出る。

- **解像度は 720p / 30fps 固定**（`CAPTURE_WIDTH` ほか）。3台同時でも帯域が足りるように
- ブラウザは**カメラが切断されるとストリームが死に、自動復帰しない**。本番で映像が止まったら `R`
- `isReady()` は p5 の `loadedmetadata` ではなく **video 要素の `readyState` を直接見ている**。
  p5 のフラグは立たないまま映像だけ来ることがあり、その場合サイズが 300×150 のまま残る

## MIDI コントローラー

**Akai APC40 MkII で操作できるようにしてある。**接続・番号の調べ方・割り当ての案は
[midi-setup.md](midi-setup.md) にまとめた。

仕組みは単純で、**MIDI を「キーを押したこと」に翻訳して、キーボードと同じ入口
（`sketch.js` の `handleKey()`）へ流している。**

```
APC40 MkII → midiManager.js → midiMap.js で キー に翻訳 → handleKey('3') → sceneManager
```

| | |
|---|---|
| **シーン側に手を入れなくてよい** | 機能はすべてキーで動くので、MIDI 対応は翻訳するだけで済む |
| **どちらからでも同じ操作ができる** | 本番で MIDI が死んでもキーボードで続けられる |
| **割り当ての変更は1行** | `js/midiMap.js` の対応表を書き換えるだけ。他へ影響しない |

### 表は3層（レイヤー → 選択中のシーン → 全体）

グリッドは 8×5 = 40 で、全操作を1パッド1機能では入れられない。そこで対応表を3層にして、
**レイヤーの表 → 選択中のシーンの表 → 全体の表** の順に引いている。

```js
const MIDI_MAP = {
    layers: { 'n:32': 'slot:1:1', 'n1:51': 'select:1' },   // レイヤーまわり（機材の列に固定）
    scenes: {
        '3': { 'n:19': 'Q' },                   // 幾何学を選んでいるとき → base に戻す
        '6': { 'n:19': 'A' },                   // カメラを選んでいるとき → オリジナル
    },
    global: { 'n:35': 'L' },                    // どのシーンでも効く
};
```

**同じ `n:19` が、選択中のシーンによって別の操作になる。**右下の 15 個を全シーンで使い回す。

`layers` の値はキーではなく**命令**（数字は 1 始まり）。

| 命令 | 動作 |
|---|---|
| `slot:<レイヤー>:<段>` | そのレイヤーのデッキの段（上から）のシーンを出す。載せたレイヤーが選ばれる |
| `column:<段>` | 横一列をまとめて出す |
| `select:<レイヤー>` | 操作するレイヤーを選ぶ |
| `clear:<レイヤー>` | レイヤーを空にする |
| `bypass:<レイヤー>` / `solo:<レイヤー>` | バイパス / ソロの切替 |
| `blend:<レイヤー>` | 合成モードを循環 |

**`layers` は学習モードの対象外。**グリッドの列とボタン列は機材の作りに固定で対応するので、
学習で動かす意味がない。直すときは `midiMap.js` を書き換える。

番号の書き方は公式の
[APC40 Mk2 Communications Protocol v1.2](https://cdn.inmusicbrands.com/akai/attachments/apc40II/APC40Mk2_Communications_Protocol_v1.2.pdf)
に合わせている。**チャンネルを見るのはトラック列のボタンだけ**で、それ以外は仕様上チャンネルが無視される。

| 対象 | 書き方 | |
|---|---|---|
| クリップグリッド 40 個 | `n:0` 〜 `n:39` | ノート 0x00〜0x27。**チャンネルは無視** |
| トラック列（SOLO・CLIP STOP など） | `n<ch>:<note>` | ノート 0x30〜0x49 は**チャンネル 0〜7 がトラック 1〜8** |
| トラックフェーダー | `c1:7` 〜 `c8:7` | **8本とも CC 0x07。チャンネルが何本目かを表す**ので見る |
| SCENE LAUNCH 1〜5 | `n:82` 〜 `n:86` | ノート 0x52〜0x56。チャンネルは無視 |
| MASTER FADER | `c:14` | CC 0x0E |
| TAP TEMPO / NUDGE − / NUDGE ＋ | `n:99` / `n:100` / `n:101` | ノート 0x63〜0x65。LED は無い |
| METRONOME | `n:90` | ノート 0x5A。**拍の頭をそろえる**に使っている |
| TEMPO つまみ | `c:13` | CC 0x0D。**回した量だけを送る**（1〜63 が＋、127〜64 が −）ので `encoders` 表で受ける |
| そのほかのつまみ | `c:16` | チャンネルを見ない（理由は下記） |

**既定値は公式プロトコルの番号で埋めてあるので、何もしなくても動く。**
グリッドは `Clip Launch 1`〜`40` = ノート 0〜39 で、**盤面では下から上へ番号が増える**（実機で確認済み）。

**縦の列 = レイヤー**にしてある（Ableton のトラックと同じ考え方）。列の真下のフェーダーが
そのレイヤーの不透明度なので、手元の並びと画面の結果が一致する。

```
          列1     列2     列3   │ 列4    列5    列6     列7    列8
最上段  ┌──────┬──────┬──────┐ ┌──────┬──────┬──────┬──────┬──────┐    SCENE
32-39   │ 流体 │カメラ│ 白線 │ │  L   │  K   │  ,   │  B   │  V   │ ← LAUNCH 1
        ├──────┼──────┼──────┤ ├──────┼──────┼──────┼──────┼──────┤
24-31   │トンネル│     │幾何学│ │  N   │  M   │  P   │SPACE │  I   │ ← 2
        ├──────┼──────┼──────┤ ├──────┴──────┴──────┴──────┴──────┤
16-23   │ 格子 │      │ 同心 │ │                                  │ ← 3
        ├──────┼──────┼──────┤ │   ★選択中のレイヤーのシーンの操作   │
 8-15   │  黒  │      │      │ │      （15 個。上の段の左から）      │ ← 4
        ├──────┼──────┼──────┤ │                                  │
```

列1〜3 の中身は `sceneManager.js` の `deck`（[デッキ](#デッキどのレイヤーで何を出すか)）。
右下 15 個は**全シーンで使い回す。**Scene03 の 15 個がそのまま枠の広さを決めている。
列4〜8 のボタン列とフェーダー4〜8 は空き。

**配置を変えたとき（2026-10-31）に学習結果の保存先を `vj-midi-map-v2` に変えた。**
旧配置で学習した結果はグリッドの列1〜3 を上書きしてしまうので読まない（ブラウザには残っている）。

### 学習モード（`;`）で割り当てる

数十個を手で書くのは現実的でないので、**押していくだけで表ができる**ようにした。
学習するのは全体操作・つまみ・シーンの操作で、レイヤーまわり（`layers`）は聞かれない。

1. コントローラーを挿して `index.html` を開く
2. `;` を押す。画面の中央に「次に押す → `[ Q ]` 幾何学 base に戻す」と出る
3. 割り当てたいパッドを押す。記録して次へ進む
4. 全部終わると、`midiMap.js` に貼れるコードがコンソールに出る

| 学習中のキー | |
|---|---|
| `-` | この操作は割り当てずに飛ばす |
| `Backspace` | 1つ戻ってやり直す |
| `;` | 途中でやめる（そこまでの割り当ては有効） |

**学習中は他のキーが効かない。**割り当てを覚えている最中に画が変わると、何が起きたのか
分からなくなるため。全体操作に使ったパッドをシーン固有に割り当てようとすると拒否する
（そのシーンでだけ全体操作が死ぬ事故を防ぐ）。**レイヤーの表のパッド（列1〜3 など）も拒否する**
（レイヤーの表が最初に引かれるので、割り当てても効かないため）。

学習結果は**ブラウザにも保存される**ので、リハ中に読み込み直しても消えない。
`midiMap.js` に貼って恒久化したら `midiManager.clearLearned()` で保存を消す。
いまどちらが効いているかは操作ウィンドウの MIDI カードの「割り当て」に出る。

### つまみ（連続値）

パッドが「押した瞬間」を送るのに対し、**つまみは回した位置そのものが届く**（CC）。
キーへの翻訳を通さず、値をそのままシーンへ渡している。表は global / scenes の2層で、
全体のつまみが先に引かれる。

```js
knobs: {
    global: {
        'c1:7': 'opacity1',                // フェーダー1 → レイヤー1 の不透明度
        'c:14': 'brightness',              // MASTER FADER → 出力全体の明るさ
    },
    scenes: {
        '9': { 'c:16': 'weight' },         // シーン9 を選んでいるとき → 線の太さ
    },
}
```

全体のつまみは `sceneManager.knobs` に宣言してある。レイヤーの不透明度は `target` に
レイヤーを持たせて、`sceneManager` 自身ではなくそのレイヤーの値を動かしている。

シーン側は動かしたいパラメータを宣言するだけでよい。

```js
// Scene09 のコンストラクタ
this.knobs = [
    { name: 'weight', label: '線の太さ', property: 'weightScale', min: 1, max: 6 },
];
```

`min` が**絞りきった状態**になる。**いまの見た目を `min` に置いておけば、つまみを下げても
元の絵に戻るだけ**で崩れることがない。0〜127 が `min`〜`max` に線形で写る。

**つまみは絶対値で届く。**シーンを切り替えるとノブの位置と実際の値がずれるので、
現在値は操作ウィンドウの「つまみ」カード（レイヤーの不透明度は「レイヤー」カード）に数字とバーで出している。

### 出力全体の明るさ（マスター調光）

**MASTER FADER（CC `0x0E`）を下げると、どのシーンを出していても画面が暗くなる。**
下げきりで真っ黒、上げきりでそのまま。**2026-10-31 にフェーダー1から移した**
（フェーダー1〜3 はレイヤーの不透明度になった）。

```
ポストシェーダーの最後       col.rgb *= u_brightness;
```

**いちばん最後に掛けている**ので、シーン・エフェクト・画面分割の状態にかかわらず必ず効く。
シーンを黒へ切り替える方法（Scene02 や `P` の切替フェード）と違って**手で送れる**のが利点で、
曲間で少しずつ落とす・アタマで一気に上げる、といった使い方ができる。

値は `sceneManager.brightness`（0.0〜1.0、起動時 1.0）。**フェーダーは絶対値で届く**ので、
本番前にフェーダーを上げきっておくこと。下がったまま触ると、その位置に画が飛ぶ。

### パッドを光らせる

**割り当てのあるパッドが光る。**暗いブースでどこが使えるか、いまどうなっているかが盤面で分かる。

| 色 | |
|---|---|
| **白** | 列1〜3: そのレイヤーでいま出ているシーン |
| 暗い青 | 列1〜3: 出せるシーン（今は出ていない） |
| **明るい黄** / 暗い黄 | 画面まわり（分割・ミラー・モザイク・フェード）の ON / OFF |
| **緑** / 暗い緑 | 音まわり（マイク入力中は明るい） |
| **明るい水色** / 暗い水色 | 選択中のシーンの操作（`modes` で選ばれているものが明るい） |
| 消灯 | 割り当てなし・デッキの空きマス |

グリッドの下のボタン列（TRACK SELECTION・ACTIVATOR・SOLO・RECORD ARM・CLIP STOP）は
単色 LED で、「選択中」「出ている」「ソロ」「通常以外の合成モード」「シーンが載っている」で点灯させる。
**ボタン列の点き方は実機で未確認**（velocity 1 で点灯する前提。光らなくても操作は効く）。

**LED を光らせるにはモードの切り替えが要る。**APC40 MkII は起動時 Generic Mode で、
このままだと「押している間だけ自分で光る」ローカル制御になっている。そこで接続時に
Introduction メッセージ（sysex）を送って **Ableton Live モード（Mode 1）**に切り替えている。

```
F0 47 7F 29 60 00 04 41 01 01 01 F7
```

Mode 2（全 LED をホスト制御）ではなく Mode 1 にしているのは、**つまみの LED リングを
APC 側が勝手に表示してくれる**ため。こちらはパッドだけ面倒を見ればよい。

**sysex の許可が要る**ので、`requestMIDIAccess({ sysex: true })` で開いている。
断られた場合は sysex 無しで開き直して、**操作はそのまま・LED だけ諦める**。
どちらになったかは操作ウィンドウの「パッドの LED」に出る。

送信は**色が変わったパッドだけ**。加えて、押し離しした位置はその場で送り直し、5秒に1回は
全部送り直している（**機器が押し離しで自分の LED を書き換えることがある**ため）。

### 学習項目を増やす

シーンを追加すると**そのシーンの操作が自動で学習項目に入る。**
（シーンを出す操作はデッキ＝ `deck` に置けばグリッドから出せる。学習はしない）
拾われるのは次の3つ。

| 出どころ | |
|---|---|
| `this.modes` | 切替を宣言していれば自動で入る（[シーンに「切替」を持たせる](#シーンに切替を持たせる)） |
| `this.keyHelp` | それ以外のキー。`[{ key: 'Q', label: '位置を引き直す' }]` の形で書く |
| `this.knobs` | つまみ。そのシーンのキーの後にまとめて聞かれる |

どのシーンでも効く操作を足すときだけ `midiMap.js` の `MIDI_GLOBAL_ITEMS` に1行書く。

学習中は**つまみの項目は CC、パッドの項目はノートしか受け付けない。**
手が当たったつまみでパッドの枠が埋まる事故を防ぐため。値が連続で届くつまみのために、
1つ記録した直後の 0.5 秒は入力を無視する。

### まだ実機で確かめていないこと

- **グリッドの下のボタン列の LED**（velocity 1 で点灯する前提で書いてある）
- **TRACK SELECTION が MIDI を送るか。**Generic Mode のままだと送らない。sysex が通って Mode 1 に
  切り替わっていれば送るはず。送らなくても、グリッドでシーンを出せばそのレイヤーが選ばれる
- **3レイヤー同時の重さ**（操作画面の fps で見る）
- フェーダー4〜8・クロスフェーダーは空き

番号だけを見たいときは `.` の監視モードが使える。

```
[midi] n1:53  v127   midiMap.js に書くなら:   'n1:53': '?',
```

接続状態・学習の進み具合・最後に受けた入力は操作ウィンドウ（control.html）の MIDI カードに出る。

## 操作ウィンドウ（control.html）

**出力とは別のウィンドウに現在の状態を出す**ための画面。プロジェクターに出力を全画面で映しつつ、
手元の MacBook 側でシーン・カメラ・加工モード・音のレベルを確認するためのもの。
**操作できるのはテンポのカードだけ**（BPM の数値指定・TAP・±1・NUDGE・頭をそろえる）。

操作画面から出力への命令は、**キーや命令の文字列（`'tempo:set:128'` など）を送り、出力側で
`handleKey()` にそのまま流す。**キーボード・MIDI と同じ入口なので、操作画面にボタンを足しても
出力側は書き足さなくてよい（`statusBus.sendCommand()` / `onCommand()`）。

```
http://localhost:5502/control.html   ← 出力と同じホスト・ポートで開く
```

通信は `BroadcastChannel`（`js/statusBus.js`）。サーバーもライブラリも要らない。
`window.opener.postMessage` ではなくこちらを使っているのは、**どちらかのウィンドウを
リロードしても勝手に繋ぎ直る**ため。

出力側の変更は3か所だけ（`index.html` の script タグ、`sketch.js` の `statusBus.publishFrom()`、
`scene06.js` の `MODE_LABELS`）。状態の送信は毎秒15回に間引いてあり、**何が起きても例外を
外に出さない**ようにしてある（状態表示のために本番の描画が落ちては本末転倒なので）。

### ⚠️ 本番の設置で守ること

| | |
|---|---|
| **プロジェクターは「拡張」にする** | ミラーリングだと操作画面が客席に映る |
| **2つのウィンドウを重ねない** | **ブラウザは見えていないウィンドウの描画を完全に止める。**実測で `document.hidden = true` になり `frameCount` が停止した。出力が裏に回ると VJ そのものが止まる |
| **全画面にする順番** | 出力ウィンドウをプロジェクター側へドラッグしてから `Enter`。Fullscreen API は「そのウィンドウが今いるディスプレイ」で全画面になる |
| **同じオリジンで開く** | `localhost:5502` と `127.0.0.1:5503` は別オリジンで通信できない |

状態が届かないとき、操作画面は原因の候補を出して知らせる。
